# Source record: configurable coordinator and worker visibility

Record ID: `SRC-2026-08-29-DSH-WARM-CONFIGURABLE-COORDINATOR-WORKER`

Status: user-authorized intent revision superseding the fixed second-turn full-catalog and zero-Host-modification requirements. It does not accept a realization.

## Desired effect and authority

The user retained the v4-pro warm-minimal purpose and replaced the fixed post-bootstrap behavior with a configurable coordinator/worker model. The main agent should keep a small model-visible interface and concentrate on local inspection, integration, coordination, and user interaction. Delegated child agents should receive the broader execution interface. Hiding a tool from the main agent is context control only: the package must not reject an otherwise valid explicit call merely because that tool schema was hidden.

The user also corrected the realization constraint. DeepSeek Harness source may be changed when target support is needed. The intent package keeps desired behavior independent from one Host implementation; a Host intrusion belongs to a realization, uses nearby meta-intent ownership markers, and is bound by its LOCK and installation evidence.

## Configurable behavior

- The preliminary bootstrap round is optional. Its enabled state and user-role message are configurable; the default message remains `检查当前工作目录，确认后仅回复 Ready.`.
- A configurable short guidance contribution becomes visible to the main agent after the optional bootstrap. Its default tells the main agent that delegated agents have broader tools and that the main agent owns local inspection, integration, coordination, and user interaction.
- Prompt/context contributions and tool-schema contributions each have an inventory. Every source is assigned `parent-only`, `child-only`, or `shared` for post-bootstrap model visibility.
- Defaults distribute known DSH contributions by responsibility: user inquiry, approval-facing interaction, and delegation/coordination stay with the main agent; broad discovery and execution go to children; the minimal shell/editor and narrowly useful skill access may be shared. Unknown contributions default to `child-only`.
- The configuration is available on the official Plugins settings page when the target supports that extension. A package-owned page or link is a fallback only when the official page cannot host the controls.

## Checked target reality

- The current warm-minimal realization stops filtering after bootstrap but its preset mounts only the minimal shell/editor composition. It therefore cannot expose the Standard preset's scoped roster merely by returning the assembled catalog unchanged.
- `router-standard` mounts a full roster and projects a minimal first request, which is the closer composition model for the revised behavior.
- The Host system-prompt assembly exposes section/context/tool names but not stable contribution ownership. A reliable source inventory and unknown-source policy require Host metadata or another Host-owned inventory rather than guessing package ownership from display names.
- The official Plugins page already pairs a Host settings namespace with a browser card contributed by an out-of-tree plugin. The settings protocol can persist structured configuration, while a package-owned card must render the two assignment lists.
- In-process children inherit the parent's preset and scoped prompt/tool contributions. An inherited complete prompt or restrictive parent scope cannot be widened in a child. The revised realization therefore needs role-aware projection or a Host composition primitive that separates main-agent presentation from delegated-child presentation.
- The current warm listener filters only `system-prompt/assemble`; it does not change the executable tool registry. This matches the user's explicit-call requirement and remains the intended distinction.

## Classification and consequence

This is an `intent_revision`. The prior STATE required one complete sentence on every provider request, prohibited AGENTS/skills/delegation material, restored the whole naturally assembled tool catalog to the main agent, and prohibited Host source changes. Those requirements are superseded by the configurable coordinator/worker visibility model.

Candidate `0.1.0-candidate.6` remains evidence for the two-tool bootstrap and native transcript path but is stale for the revised STATE. A replacement realization must verify the settings UI, source inventory, role-specific model-visible assemblies, unknown-source default, optional bootstrap, and the absence of package-added execution rejection. Any Harness intrusion must be locally marked and lifecycle-managed; it is not promoted into STATE as the only valid implementation.
